# Manual Test Cases — ARW-17: Overdue Tasks Widget – Display Applied Payer Category Filter

**Jira**: https://vwiki281-1785763863770.atlassian.net/browse/ARW-17
**Module**: `sup_dashboard`
**Date**: 2026-08-31
**Application**: RevFlow — Supervisor Dashboard (`/dashboard`)
**Total Cases**: 6

## Story Goal

Provide users with a clear visual indication that the **Overdue Tasks** widget data is filtered by the selected **Payer Category**, and allow them to view the applied filter through the tooltip.

## Acceptance Criteria → Test Case traceability

Every test case below maps 1-to-1 onto a literal clause of an acceptance criterion in ARW-17. No behaviour outside the story is asserted.

| AC | Story clause | Test Case |
|----|--------------|-----------|
| AC1 | When the **Income** Payer Category filter is applied, the Overdue Tasks widget should display the filter icon/indicator | TC1 |
| AC1 | When no Payer Category filter is applied, the filter indicator should not display an applied filter | TC2 |
| AC2 | When the user hovers over the filter indicator on the Overdue Tasks widget, a tooltip should be displayed | TC3 |
| AC2 | The tooltip should show "Payer Category Filters (Income)" | TC4 |
| AC3 | When the user **changes** the Payer Category filter, the Overdue Tasks widget's filter indicator and tooltip should reflect the current applied filter | TC5 |
| AC3 | When the user **removes** the Payer Category filter, the Overdue Tasks widget's filter indicator and tooltip should reflect the current applied filter | TC6 |

## Notes

- **Scope**: assertions target only the **Overdue Tasks** widget (`arw-overdue-tasks-widget`), as specified by the story. The Payer Category filter is a Dashboard-header control shared by all widgets, so applying it also affects other widgets — that behaviour is out of scope for ARW-17 and is not asserted here.
- **RBAC**: ARW-17 states no role-specific behaviour for the Overdue Tasks filter indicator, so no permission cases are derived. Access control to `/dashboard` itself is out of scope for this story.
- **Test data**: `Income` is the only Payer Category named in the story and is used throughout. TC5 requires a second category purely as the "changed to" value; the story does not name one, so any other available category may be used.
